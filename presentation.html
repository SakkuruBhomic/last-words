03 // ARCHITECTURE DEEP-DIVE

Why Zero-Database & Static Generation (SSG)?

The Architectural Philosophy

  • • Historical Telemetry is Immutable: Surveyor 3 landed in 1967; Opportunity's final signal was in 2018. Historical telemetry data does not mutate based on dynamic user queries.
  • • 0ms Database Latency: Traditional client-server DB requests add 100–400ms latency and connection pool failures. SSG delivers pre-rendered HTML in under 30ms.
  • • Zero Infrastructure Cost: No cloud database hosting bills, no cold starts, no connection leak bugs, and immune to DDoS query exhaustion.
  • • Air-Gapped Ready: Perfect for museum exhibits, planetarium kiosks, and classroom labs with restricted external internet access.

The Next.js 16 Static Pipeline

  • 1. src/data/machines.ts: Single source of truth containing typed mission telemetry and coordinates.
  • 2. generateStaticParams(): App Router walks all 8 machine slugs at build time to output static HTML.
  • 3. generateMetadata(): Derives SEO titles, meta tags, and OpenGraph descriptors statically per mission.
  • 4. prebuild Hook: Automatically runs validate-data.mjs to ensure strict schema compliance before any build artifact is emitted.
Result: 100% deterministic, type-safe builds with instantaneous edge CDN propagation.

12 // FEATURE DEEP-DIVE

Hydration-Safe Silence Clock

Solving Next.js Hydration Mismatch

In server-rendered React applications, calculating a live clock during SSR creates a fatal mismatch between the server timestamp (T1) and the client hydration timestamp (T2).

  • • useMounted Hook (src/lib/useMounted.ts): Defers live clock calculations until after the initial DOM mount has completed.
  • • Zero SSR Flashing: Renders a clean static baseline during server rendering, then smoothly initiates the live tick.
  • • Zero Console Errors: Completely eliminates React Hydration Error 418/423 in production builds.
